# ADR-0003: Recover Paseo 0.7.2 executions by reconciliation, not plugin memory

- **Status:** Accepted
- **Date:** 2026-09-06
- **Beads Task:** `dir-m0.2`
- **Plan gate:** M0 plugin and execution lifecycle
- **Decision owner:** `dir-m0.2` Task owner
- **Aligned with:** [ADR-0005](0005-session-scoped-mcp-provider-matrix.md), [ADR-0008](0008-director-threat-model.md), and [ADR-0010](0010-top-level-task-agent-parentage.md)
- **Amended by:** [ADR-0011](0011-linux-only-platform-scope.md), which establishes Linux as the sole `1.0` platform, and [ADR-0020](0020-zero-work-bootstrap-and-terminal-event-dispatch.md), which replaces prompted creation for Director-launched top-level workers

## Context

ADR-0002 admitted a narrow exact-0.7.2 public Paseo subset but deferred runtime behavior. Director must survive plugin reload, disable, crash, daemon restart, and agent interruption without losing or duplicating a Run. PLAN v0.3 and ADR-0010 require independent top-level Task Agents and Reviewer Agents, optional Task-Agent-created helpers, durable effect records, startup reconciliation, at most one recoverable top-level Task Agent replacement, and `Needs you` for ambiguity.

Paseo 0.7.2 exposes public plugin status, SDK subscriptions, workspace/agent list and handles, correlation labels, provider persistence metadata, and archive. It does not expose a server version/feature accessor, an SDK cancel operation, or a transaction joining Director's TaskStore to Paseo's native records. Correctness therefore cannot depend on plugin memory, a cleanup callback, or a single event delivery.

## Question or hypothesis

Can exact Paseo 0.7.2 support a fail-closed Director lifecycle in which public state is recoverable after every relevant plugin/daemon interruption, active archive closes the provider runtime, PLAN v0.3 agent topology remains observable without duplication, and ambiguous execution is detected instead of repeated?

## Acceptance criteria

- Install and exercise a disposable exact-0.7.2 plugin on a password-protected headless daemon.
- Observe reload, disable/enable, plugin crash, and daemon restart.
- Recover stable native workspace/agent IDs and Director labels with public list/ref/refresh operations.
- Demonstrate subscription wake-ups without treating delivery or counts as authority.
- Exercise an initialized idle restart, restart during an active turn, active agent archive over a proven live child/provider process tree, and workspace archive.
- Create concurrent independent top-level Task Agents in distinct worktrees, with omitted parents and exact Task titles, plus an independent top-level Reviewer in a detached checkout.
- Exercise a parent-bound helper with durable scope/accounting facts, explicit and cascade interruption, recovery, cleanup, and no Task/Run/Candidate ownership promotion.
- Prove a same-title top-level Task Agent replacement starts only after the prior agent is `closed`, has non-null `archivedAt`, and external termination facts reconcile.
- Check every required client/root/ref-handle method before create and reject each missing structural capability before a test side effect.
- Define authoritative facts, recovery transitions, compatibility bounds, and cleanup.

## Evidence

The complete sanitized transcript, lifecycle matrix, fixture hashes, reproduction commands, and cleanup proof are in [Paseo 0.7.2 lifecycle evidence](../evidence/m0.2/paseo-0.7.2-lifecycle.md).

The bounded run used:

- `@getpaseo/plugin`, `@getpaseo/client`, and `@getpaseo/protocol` 0.7.2;
- the globally installed Paseo CLI/server distribution 0.7.2;
- Node.js 26.7.0 on Debian 13 Linux x86_64, while preserving the documented Node.js 22 implementation floor;
- an isolated loopback daemon requiring a password, with relay and MCP disabled;
- the `--no-web-ui` headless variant for the final install check;
- one discovered ready provider/model for bounded execution, `codex/gpt-5.4-mini`.

ADR-0005 independently admits this exact Codex CLI/provider tuple for session-scoped MCP and exact tool preapproval. This spike uses it only as the lifecycle witness. It does not generalize helper behavior to another provider, duplicate ADR-0005's MCP proof, or treat MCP policy as the authority boundary rejected by ADR-0008.

Key results:

- unauthenticated public CLI access was rejected;
- exact scaffold and fixture typechecks passed;
- one shared effect-free preflight covered 43 required client, root, Workspace, Agent, and timeline methods before and after connection in both harnesses; removing each method independently failed precisely with zero side effects in each harness;
- the incompatible fixture failed before its first marker write;
- reload, disable, authenticated documented daemon stop, and explicit worker-plus-supervisor `SIGINT` invoked plugin cleanup; plugin crash, worker `SIGKILL`, and process-group `SIGINT` did not provide that callback;
- an enabled plugin automatically loaded after daemon restart;
- IDs, labels, native provider session references, and archived records survived restart;
- subscriptions emitted wake-ups, while fresh list/ref/refresh reconstructed the state;
- a durable marker and `/proc` ancestry proved one long-running child and two provider PIDs live under the isolated daemon before active archive; the final exact-fixture run returned from archive in 396 ms with all three gone, they remained absent, public state became `closed` with non-null `archivedAt`, retry was idempotent, and the workspace remained usable;
- no archive child received `SIGINT`, `SIGTERM`, or `SIGHUP`; archive hard-killed the observed process tree and therefore cannot implement graceful pause or safe-boundary parking;
- workspace archive was idempotent, removed the workspace from active discovery, cascaded an `archivedAt` to an unarchived Reviewer, and did not erase the archived agent handle;
- authenticated documented stop restarted every unarchived idle, Reviewer, replacement, Task, and helper record as `closed` with null `archivedAt` and no `activeTurn`; those records remained resumable, ambiguous, and capacity-consuming;
- abrupt worker `SIGKILL` auto-restarted under the same supervisor, preserved idle records as `idle`, and projected interrupted active records as `running` with no `activeTurn`; later public sends resumed the same provider sessions only after reconciliation;
- a no-prompt record could not resume after restart because no provider rollout existed; archive plus one atomically prompted replacement was successful;
- two top-level Task Agents were simultaneously `running` against one source repository in distinct Paseo-managed worktrees; each had an omitted parent, an exact undecorated Task title, a unique ID/workspace/session/prompt marker, and one label-filtered match through every plugin transition;
- an independent top-level Reviewer had an omitted parent, the exact configured review title, and a separate workspace over a detached checkout of the exact Candidate SHA; it completed its unique prompt, survived restart, and archived independently;
- two helpers created through the public parent option carried the exact observed parent label and were forced to the parent Task Agent's workspace even when the fixture requested the sibling Task and Reviewer directories; durable fixture accounting reported two Task Agents, one Reviewer, two helpers, five of eight global slots, two of three helper slots for the owning Run, and two of two Task slots for the Director Workspace;
- explicit helper archive terminated its proven live child/provider chain without interrupting its parent; parent archive cascaded to the other helper and terminated both proven live chains; recovery retained their parentage and closed identities;
- a replacement Task Agent was created 816 ms after the prior agent's archive timestamp, with a new native ID, the same exact Task title, no parent, the same Execution Workspace, and exactly one unarchived Task Agent for the Run.

## Authoritative facts

Director treats these public facts as authoritative:

1. its TaskStore effect and Run records;
2. Git/worktree and forge observations for external effects;
3. Paseo workspace/agent results reconstructed by ID and Director labels with `list`, `ref`, and `refresh`;
4. public plugin status for loaded/disabled/failed state;
5. agent `status`, `activeTurn`, `archivedAt`, and provider persistence fields as observations that still require cross-system reconciliation.
6. the public `paseo.parent-agent-id` label for helper parentage, plus Task/Run/role/intent labels and native workspace placement checked against Director's durable records.

Paseo does not define Director Task, Run, Candidate-owner, quota, or budget semantics. Those remain Director TaskStore facts. The public substrate supplies native identity, parentage, placement, lifecycle, and usage observations; Director must persist the role/ownership and reservation ledger before admitting helper work.

For Director lifecycle decisions, native termination requires all of: `status=closed`, non-null `archivedAt`, and reconciled external process/effect facts. `closed` with null `archivedAt` is not termination. Every null-`archivedAt` record consumes capacity regardless of `status` and blocks replacement, duplicate prompting, new capacity, branch/workspace cleanup, and any inference that the Run ended.

SDK subscriptions are edge-triggered wake-ups only. Plugin callbacks, process markers, logs, and in-memory handler state are not product authority. The Linux marker/process probes validate this spike's termination claim but are not production dependencies.

## Alternatives considered

### Resume from plugin memory and callback order

Rejected. Plugin memory disappears on every reload or process loss. The returned cleanup callback was observed for reload, disable, authenticated documented `paseo daemon stop --home`, and explicit `SIGINT` to both worker and supervisor. It was absent for plugin exit, abrupt worker `SIGKILL`, and process-group `SIGINT`, where the plugin process receives the signal with the CLI group. Callback behavior therefore depends on the shutdown path. It is useful for best-effort resource release, never durable correctness.

### Treat persisted status as termination or liveness

Rejected. Orderly full-daemon restart returned all unarchived records as `closed` with null `archivedAt` and no `activeTurn`; they remained resumable. Abrupt worker loss returned interrupted records as `running` without `activeTurn` while idle records remained `idle`. None of those projections alone proves liveness, completion, failure, or termination. Treating status as permission to retry, replace, free capacity, or clean could duplicate or destroy a Run.

### Archive and replace every agent after restart

Rejected as the default. Initialized provider sessions resumed successfully with the same native agent and provider-session IDs. Automatic replacement would discard useful continuity and risk duplicate work. Replacement remains limited to one attempt after explicit non-resumability or another reconciled recoverable failure, and only after archive produces `closed` plus non-null `archivedAt` and external termination facts reconcile.

### Create Task work through the parent mechanism

Rejected. The parent option deliberately marks a helper and binds its public parentage and lifecycle. Task Agents and Reviewer Agents instead use the top-level client workspace handle with the parent field omitted. The live matrix observed no parent for both top-level roles and an exact parent ID only for helpers.

### Use private cancellation, database, or protocol operations

Rejected. Those surfaces are outside the supported public plugin/SDK contract and violate the PLAN. Public archive is sufficient to close the runtime; unresolved ambiguity escalates rather than reaching into internals.

### Reconcile durable facts, then resume, archive/replace, or escalate

Selected. It matches the PLAN's effect model and is the only observed path that handles both resumable provider sessions and interrupted ambiguous work without assuming exactly-once delivery.

## Decision

**Go**, bounded to exact Paseo 0.7.2 and the following mandatory lifecycle protocol.

### Creation

1. Persist Director's Task/Run intent and deterministic correlation labels before calling Paseo.
2. The engine creates Task Agents and Reviewer Agents through a top-level SDK client in their already-recorded workspaces and omits `parent`. A Task Agent title is exactly its Task title; durable IDs and labels carry correlation.
3. Create the native agent with its initial prompt in the same public create request. Do not intentionally create an empty provider record and depend on a later first send.
4. Persist the returned workspace ID, agent ID, labels, provider/model/mode, and any public persistence reference before another Director effect.
5. Re-list by labels when a create response is lost. Never create a second native record until reconciliation proves the first absent or the one-replacement rule explicitly applies.

### Helpers and replacement

1. A helper is admitted only from its creating Task Agent's fixed Project/Task/Run envelope. Reserve its per-Run idempotency key, helper quota, Run budget, and global capacity before creation.
2. Use the public parent mechanism and persist the observed native helper ID before helper work. Verify its exact parent label, fixed Director labels, and admitted workspace placement. An unknown result parks; it is never blindly retried.
3. A helper remains role `helper`. Its ID can never replace the durable Task owner, Run owner, Candidate producer of record, or independent Reviewer.
4. Explicit helper archive is the normal containment operation. Parent cascade is a proven safety net, but Director still reconciles helpers explicitly before Task workspace cleanup.
5. A recoverable top-level Task Agent replacement keeps the same exact Task title and workspace, omits `parent`, receives durable Run facts, and may be created only after public reconciliation proves the prior Task Agent is `closed`, has non-null `archivedAt`, and has no surviving external process or ambiguous effect. At most one replacement is allowed.

### Startup, reload, and reconnect

1. Run exact-package compile checks before release. Before any native create or other engine side effect, check client lifecycle, every required SDK root, and effect-free `ref()`-derived Workspace, scoped-agent, Agent, and timeline handle methods. Repeat the runtime check after connection.
2. On startup or reload, subscribe first, run a complete list/ref/refresh reconciliation, and then process any wake-ups that arrived during the scan.
3. Reconstruct all engine work from TaskStore and native references. Never resume from plugin memory.
4. When public plugin status is `failed`, stop effects. Reload only after recording the interruption and reconciling native/external facts.
5. Treat cleanup callbacks as best effort. Authenticated documented stop and explicit worker-plus-supervisor `SIGINT` ran cleanup in the tested topology; plugin crash, worker `SIGKILL`, and process-group `SIGINT` did not. Durable recovery must work for every path without the callback.

### Agent interruption

1. Native termination requires `status=closed`, non-null `archivedAt`, and reconciled external facts. Agent archive is safe to retry. The admitted version's lifecycle suite must separately prove that an already-running provider/tool process tree actually terminates.
2. `closed` with null `archivedAt` after orderly restart is an un-terminated, resumable, ambiguous, capacity-consuming projection. It cannot authorize replacement, another launch, duplicate prompting, branch/workspace cleanup, or released capacity.
3. `running` with no `activeTurn` is the interrupted/unknown projection observed after abrupt worker loss. It is not proof that work is executing and not permission to retry it. Idle records may remain `idle` across the same worker restart and are also still capacity-consuming while unarchived.
4. Reconcile TaskStore, Git/worktree, GitHub, native IDs/sessions, process absence, and other effect-specific evidence before sending another prompt.
5. If the prior outcome is proven and continuation is safe, a public send may resume the same initialized provider session. This is recovery, not a duplicate prompt authorization.
6. If the native record explicitly cannot resume, archive it, confirm the full termination predicate, and apply at most one replacement using the durable Run facts.
7. If any non-idempotent outcome remains ambiguous, enter `Needs you`; do not send, retry, replace, free capacity, or clean automatically.

### Cleanup

1. Archive every Director-owned unarchived agent, including `closed`/null-`archivedAt`, before treating it as terminated; retrying archive is allowed.
2. Archive all Director-owned agents before archiving their workspace. Workspace archive also cascades archive to contained unarchived agents; record those agent timestamps explicitly rather than relying on cascade as ordinary control flow.
3. Agent archive hard-killed the observed child/provider tree without delivering `SIGINT`, `SIGTERM`, or `SIGHUP` to the child. It is an emergency/termination mechanism, not PLAN pause or safe-boundary parking.
4. Workspace archive is safe to retry and removes the Paseo-managed worktree directory, but exact-0.7.2 left the Task branches and an empty worktree-root directory. Director owns verified branch/ref and residual-directory cleanup; Paseo archive is not evidence that they are gone.
5. Archived agent references remain part of the audit record. Delete filesystem/process/Git resources only after ownership and the full archive/termination predicate are proven under PLAN cleanup policy.

## Compatibility checks

Paseo v0.7 mixed entries transform recognized client contribution calls out of server execution. Client UI contributions must therefore be checked against the exact package at compile time, while the server context and public SDK are checked structurally in their actual runtimes. The SDK preflight derives handles with synchronous effect-free `ref()` calls and validates the methods on those handles without calling create, send, archive, or another effect. Dynamically demanding client-only contribution methods from the server object is invalid.

The absence of a public daemon version remains unresolved. Director admits only explicitly tested host distributions and reruns this compile/structural/lifecycle suite for another 0.7.x build. v0.8 still requires a separate migration decision.

## Consequences

- The plugin engine may recover after reload, disable/enable, plugin crash, or daemon restart without duplicating native records.
- The public exact-0.7.2 substrate can represent PLAN v0.3's top-level Task/Reviewer topology, concurrent worktree isolation, parent-bound helpers, and non-overlapping replacement. Director must still supply durable intents, role ownership, capacity/budget accounting, and fail-closed admission.
- Crash and orderly-restart recovery are reconciliation-driven and may deliberately stop at `Needs you`.
- Every unarchived native record consumes capacity. Neither stale `running`, ordinary `idle`, nor `closed` with null `archivedAt` can drive retry, replacement, launch, or cleanup decisions.
- Agent creation must be atomically prompted; empty-agent creation is not an allowed Director path.
- Public archive satisfies the stable adapter's hard interrupt/close need for the tested version: it terminated a proven live child/provider process tree promptly without a graceful child signal. It still does not prove what an interrupted tool already changed and cannot implement safe-boundary pause.
- Paseo workspace archive owns native workspace/worktree lifecycle and cascades agent archive, but Director retains ownership of Task branch/ref and residual-directory cleanup.
- Event consumers must tolerate duplicate, delayed, and missed wake-ups.
- M1 remains blocked until every M0 stop condition and the M0 exit gate are complete. ADR-0014 supersedes ADR-0008's No-go with the practical trusted-provider Linux boundary; parentage, worktrees, labels, MCP scoping, and provider settings alone are still not an OS or credential boundary.
- Provider-specific restart and helper behavior is not generalized from the single Codex execution. ADR-0005 owns the admitted-provider MCP matrix and requires tuple revalidation after any Paseo/provider/policy change.
- Broader Linux topology behavior remains with its M0 owners. This result creates no support contract for another host operating system.
