# ADR-0003: Recover Paseo 0.7.2 executions by reconciliation, not plugin memory

- **Status:** Accepted
- **Date:** 2026-09-06
- **Beads Task:** `dir-m0.2`
- **Plan gate:** M0 plugin and execution lifecycle
- **Decision owner:** `dir-m0.2` Task owner

## Context

ADR-0002 admitted a narrow exact-0.7.2 public Paseo subset but deferred runtime behavior. Director must survive plugin reload, disable, crash, daemon restart, and agent interruption without losing or duplicating a Run. The PLAN already requires durable effect records, startup reconciliation, at most one recoverable primary replacement, and `Needs you` for ambiguity.

Paseo 0.7.2 exposes public plugin status, SDK subscriptions, workspace/agent list and handles, correlation labels, provider persistence metadata, and archive. It does not expose a server version/feature accessor, an SDK cancel operation, or a transaction joining Director's TaskStore to Paseo's native records. Correctness therefore cannot depend on plugin memory, a cleanup callback, or a single event delivery.

## Question or hypothesis

Can exact Paseo 0.7.2 support a fail-closed Director lifecycle in which public state is recoverable after every relevant plugin/daemon interruption, active archive closes the provider runtime, and ambiguous execution is detected instead of repeated?

## Acceptance criteria

- Install and exercise a disposable exact-0.7.2 plugin on a password-protected headless daemon.
- Observe reload, disable/enable, plugin crash, and daemon restart.
- Recover stable native workspace/agent IDs and Director labels with public list/ref/refresh operations.
- Demonstrate subscription wake-ups without treating delivery or counts as authority.
- Exercise an initialized idle restart, restart during an active turn, active agent archive over a proven live child/provider process tree, and workspace archive.
- Check every required client/root/ref-handle method before create and reject each missing structural capability before a test side effect.
- Define authoritative facts, recovery transitions, compatibility bounds, and cleanup.

## Evidence

The complete sanitized transcript, lifecycle matrix, fixture hashes, reproduction commands, and cleanup proof are in [Paseo 0.7.2 lifecycle evidence](../evidence/m0.2/paseo-0.7.2-lifecycle.md).

The bounded run used:

- `@getpaseo/plugin`, `@getpaseo/client`, and `@getpaseo/protocol` 0.7.2;
- the globally installed Paseo CLI/server distribution 0.7.2;
- Node.js 26.7.0 on Debian 13 Linux x86_64, while preserving the documented Node.js 22 implementation floor;
- an isolated loopback daemon requiring a password, with relay and MCP disabled;
- the `--no-web-ui` headless variant for the final install check;
- one discovered ready provider/model for bounded execution, `codex/gpt-5.4-mini`.

Key results:

- unauthenticated public CLI access was rejected;
- exact scaffold and fixture typechecks passed;
- effect-free preflight covered 43 required client, root, Workspace, Agent, and timeline methods; removing each method independently failed precisely with zero side effects;
- the incompatible fixture failed before its first marker write;
- reload and disable invoked cleanup; plugin crash and daemon shutdown did not provide a reliable cleanup boundary;
- an enabled plugin automatically loaded after daemon restart;
- IDs, labels, native provider session references, and archived records survived restart;
- subscriptions emitted wake-ups, while fresh list/ref/refresh reconstructed the state;
- a durable marker and `/proc` ancestry proved one long-running child and two provider PIDs live under the isolated daemon before active archive; the final exact-fixture smoke returned from archive in 428 ms with all three gone, they remained absent, public state became `closed`, retry was idempotent, and the workspace remained usable;
- workspace archive was idempotent, removed the workspace from active discovery, and did not erase the archived agent handle;
- restart during an active turn yielded a persistent `running` record with no `activeTurn`; a later public send resumed the same provider session, but the interrupted turn's external outcome remained unknowable without Director reconciliation;
- a no-prompt record could not resume after restart because no provider rollout existed; archive plus one atomically prompted replacement was successful.

## Authoritative facts

Director treats these public facts as authoritative:

1. its TaskStore effect and Run records;
2. Git/worktree and forge observations for external effects;
3. Paseo workspace/agent results reconstructed by ID and Director labels with `list`, `ref`, and `refresh`;
4. public plugin status for loaded/disabled/failed state;
5. agent `status`, `activeTurn`, `archivedAt`, and provider persistence fields as observations that still require cross-system reconciliation.

SDK subscriptions are edge-triggered wake-ups only. Plugin callbacks, process markers, logs, and in-memory handler state are not product authority. The Linux marker/process probes validate this spike's termination claim but are not production dependencies.

## Alternatives considered

### Resume from plugin memory and callback order

Rejected. Plugin memory disappears on every reload or process loss, and the returned cleanup callback was not observed on daemon shutdown. Callback order is useful for best-effort resource release, not durable correctness.

### Treat every persisted `running` record as live

Rejected. An active turn interrupted by daemon restart remained `running` while `activeTurn` was absent. Treating that projection as proof of a live effect would strand the Run; treating it as proof of failure and blindly retrying could duplicate an external effect.

### Archive and replace every agent after restart

Rejected as the default. Initialized provider sessions resumed successfully with the same native agent and provider-session IDs. Automatic replacement would discard useful continuity and risk duplicate work. Replacement remains limited to one attempt after explicit non-resumability or another reconciled recoverable failure.

### Use private cancellation, database, or protocol operations

Rejected. Those surfaces are outside the supported public plugin/SDK contract and violate the PLAN. Public archive is sufficient to close the runtime; unresolved ambiguity escalates rather than reaching into internals.

### Reconcile durable facts, then resume, archive/replace, or escalate

Selected. It matches the PLAN's effect model and is the only observed path that handles both resumable provider sessions and interrupted ambiguous work without assuming exactly-once delivery.

## Decision

**Go**, bounded to exact Paseo 0.7.2 and the following mandatory lifecycle protocol.

### Creation

1. Persist Director's Task/Run intent and deterministic correlation labels before calling Paseo.
2. Create the native agent with its initial prompt in the same public create request. Do not intentionally create an empty provider record and depend on a later first send.
3. Persist the returned workspace ID, agent ID, labels, provider/model/mode, and any public persistence reference before another Director effect.
4. Re-list by labels when a create response is lost. Never create a second native record until reconciliation proves the first absent or the one-replacement rule explicitly applies.

### Startup, reload, and reconnect

1. Run exact-package compile checks before release. Before any native create or other engine side effect, check client lifecycle, every required SDK root, and effect-free `ref()`-derived Workspace, scoped-agent, Agent, and timeline handle methods. Repeat the runtime check after connection.
2. On startup or reload, subscribe first, run a complete list/ref/refresh reconciliation, and then process any wake-ups that arrived during the scan.
3. Reconstruct all engine work from TaskStore and native references. Never resume from plugin memory.
4. When public plugin status is `failed`, stop effects. Reload only after recording the interruption and reconciling native/external facts.
5. Treat cleanup callbacks as best effort. Durable recovery must work when they never run.

### Agent interruption

1. `closed` plus `archivedAt` is authoritative termination for the public adapter. Agent archive is safe to retry. The admitted version's lifecycle suite must separately prove that an already-running provider/tool process tree actually terminates.
2. `running` with no `activeTurn` after reconnect is an interrupted/unknown projection, not proof that work is executing and not permission to retry it.
3. Reconcile TaskStore, Git/worktree, GitHub, and other effect-specific evidence before sending another prompt.
4. If the prior outcome is proven and continuation is safe, a public send may resume the same initialized provider session.
5. If the native record explicitly cannot resume, archive it and apply at most one replacement using the durable Run facts.
6. If any non-idempotent outcome remains ambiguous, enter `Needs you`; do not send, retry, or replace automatically.

### Cleanup

1. Archive a Director-owned active agent to interrupt and close its runtime; retrying archive is allowed.
2. Archive all Director-owned agents before archiving their workspace.
3. Workspace archive is safe to retry, but archived agent references remain part of the audit record.
4. Delete filesystem/process resources only after ownership and archive/termination are proven under the PLAN cleanup policy.

## Compatibility checks

Paseo v0.7 mixed entries transform recognized client contribution calls out of server execution. Client UI contributions must therefore be checked against the exact package at compile time, while the server context and public SDK are checked structurally in their actual runtimes. The SDK preflight derives handles with synchronous effect-free `ref()` calls and validates the methods on those handles without calling create, send, archive, or another effect. Dynamically demanding client-only contribution methods from the server object is invalid.

The absence of a public daemon version remains unresolved. Director admits only explicitly tested host distributions and reruns this compile/structural/lifecycle suite for another 0.7.x build. v0.8 still requires a separate migration decision.

## Consequences

- The plugin engine may recover after reload, disable/enable, plugin crash, or daemon restart without duplicating native records.
- Crash recovery is reconciliation-driven and may deliberately stop at `Needs you`.
- A stale `running` projection cannot drive scheduler capacity or retry decisions until active-turn and durable effect facts are reconciled.
- Agent creation must be atomically prompted; empty-agent creation is not an allowed Director path.
- Public archive satisfies the stable adapter's interrupt/close need for the tested version: it terminated a proven live child/provider process tree promptly. It still does not prove what an interrupted tool already changed.
- Event consumers must tolerate duplicate, delayed, and missed wake-ups.
- M1 remains blocked until every M0 stop condition and the M0 exit gate are complete; ADR-0008's authority-separation No-go remains in force.
- Provider-specific restart behavior is not generalized from the single Codex execution; `dir-m0.3` owns the admitted-provider matrix.
- Windows and broader platform behavior remain with the later M0 platform lifecycle Task.
